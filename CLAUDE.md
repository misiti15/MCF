# MCF — notes for Claude sessions

- **North star (owner 2026-10-29):** build a profitable, sustaining, autonomous intraday trading system. The moves are there in the 3,000+ names, long and short; the core job is finding the best ways to identify those moves beforehand, in high numbers, and turning that into setups. Everything else serves this. See docs/BDI_CHARTER.md (Move Hunt, capture rate, "every day is a winning day in some way").

- **Read `MARCOFLOW_CONTEXT.md` first** — what the predecessor system (MarcoFlow) learned, what failed, data rules, and the owner's standing rules.
- Then `README.md` (architecture), `docs/RESEARCH.md` (setup evidence), `docs/ROADMAP.md` (phases).
- MarcoFlow history DB: `python scripts/import_marcoflow.py` rebuilds `data/marcoflow.sqlite` from `data/marcoflow_export/Folder2_Data.zip` (not in git — too large).
- MarcoFlow live data: only via `mcf/marcoflow.py` (read-only GET allow-list). Never call tick/heartbeat/secret endpoints.
- Tests: `pip install -e ".[dev,alpaca]" && pytest -q`.
- Every result screen/report carries "Educational only — not financial advice". Never write secrets to files or logs.
- **Research rules (owner): `docs/RESEARCH_RULES.md`** — costs always in, locked holdouts scored once, report every finalist and the number of configurations tried, no setup/exit changes during market hours, every approved change goes in `research/ledger.jsonl` and is re-checked with `python -m mcf.research.ledger check`.
- **Backlog:** setup/strategy ideas go to `research/backlog.jsonl` (gates in `mcf/research/backlog.py`); only housekeeping ships directly. See RESEARCH_RULES 15-17.
- Merging: Claude merges its own PRs once tests pass; PRs that touch setups/exits are merged only outside 09:30-16:00 ET (the `setup-freeze` check enforces it).
- **Setup moves (owner 2026-10-20):** every promotion / demotion / move regenerates `docs/live/assignments.json` (`python -m mcf.report.assignments`) in the same commit, so the dashboard shows the new assignment and its timestamp at once (`tests/test_assignments.py` enforces it).
- **Promotion = move (owner 2026-10-20):** a promoted setup is switched off in the account it came from in the same change; it never runs as a copy in two accounts unless the owner asks.
- **Account names (owner 2026-11-11):** Primary; On Deck (key `testing`) = promotion candidates, 2-3x Primary's size so each gets maximum exposure, eventually ~15-30 setups; Testing A / B / C (keys `testing2` / `explore1` / `livelab`) = testing areas; Setup Generator (`gen`) and Graveyard unchanged. Setups advance testing area → On Deck → Primary. On/off switch experiments are field-tested only in the testing areas, never in On Deck or Primary. Internal keys, branches, `MCF_ACCOUNT` values and order prefixes are unchanged; older notes use the old names (Testing 1 = On Deck, Testing 2 = Testing A, Explore 1 = Testing B, Live Lab = Testing C).
- **Testing 1 = Testing 2 (owner 2026-10-23; superseded 2026-11-11 by the tier structure above):** the two testing accounts carry equal weight for promotion; two accounts exist only to give more setups exposure. Never treat Testing 2 as a lower tier.
- **One-big-day check (owner 2026-10-25):** every promotion / demotion / review shows the setup's avg R *without its best session* and that session's share of total R (dashboard column "Avg R w/o best day", `1 day` tag at ≥ 50%). A record carried by 1-2 big days must be called out.
- **Rule-change context (owner 2026-11-02):** whenever stats or figures are given (chat, briefs, posts, reviews), note alongside them any rule / config change in effect before or after a date inside the window (from `research/ledger.jsonl` effective dates: sizing, stops, filters, timing fixes, moves), so setup results are never mixed up with rule changes.
- **Trimmed setups (owner 2026-11-03, updated 2026-11-04):** any setup trimmed for low activity moves to a testing account for more exposure; it is never just switched off. Low-rep setups (< 20 live trades from On Deck / Testing A, < 10 from the Graveyard) rotate through the testing areas (Testing A / B / C; originally Explore 1 / Live Lab, the low-rep homes, owner ROLL1 2026-11-04, updated 2026-11-11; re-evaluated every ~2 sessions; research/ops/lowrep1104/NOTES.md). Their setups show on the leaderboard with the account tag (Graveyard-origin ones stay off); their account totals stay out of the daily post.
- **Playing time (owner 2026-11-03):** low-activity setups must get a fair chance; a system that starves them fails at producing quality results. Fix starvation by session rotation (whole sessions off for top-trade setups, logged as benched, excluded from per-session stats), never by in-session throttling in Primary/Testing; no reports unless a decision is needed.
- **Research mindset (owner 2026-11-04):** every test, study and research run is done with optimism — built and run in the hope and expectation of making progress (look for what works, what can be salvaged, the next step), while results are still reported honestly with costs in and no inflation.
- **Remedies (owner 2026-11-05):** when a problem hurts R — per setup, per day or per category of setup — pursue a remedy that is targeted: it fixes the failure mode where it occurs, is not tailored to one setup, and is not so broad that it hurts many setups. Every remedy test reports its effect on each affected setup/family (how many improve, how many get worse and by how much), not only the total.
- **Testing arena (owner 2026-11-12):** Testing A–F + Setup Generator are ONE arena with invisible enclosures, all treated the same; keep exposure balanced across them so their capacity is fully used. Every 4 sessions the ~15 least-traded arena setups get a spotlight account (sized so it doesn't starve others), then everything is re-scored. Graveyard is separate (setups leave only on transfer-worthy stats; its trades still count in EOD totals). Only promotions to On Deck or Primary need the owner; rotation needs no reports.
- **Direction research anchor (owner 2026-11-14):** the system never enters at 9:30 (volatility). Market-direction research (Market Compass, up-day / leveraged-ETF work) is anchored AFTER the first ~20 minutes: reference = the ~09:50 state and the 09:30-09:50 range, not the 9:30 open or the prior close; study what happens after the early swings (e.g. a dip in the first 20 min then a turn up) and score readings by the return after the decision time.
- **Workbench variants (owner 2026-11-15):** a setup reworked on the Workbench becomes a COPY with its own id (`<parent>-WB<n>`), labelled differently; the parent is never changed. Each variant is tested independently on the SAME tests as its parent: the replay sessions AND the 2-year backtest (costs in, locked block untouched, configs counted). Owner 2026-11-16: parent and copy are tested the exact same way (same backtests: live-session replay + 2-year; the parent's live stats are not used); the copy leaves if it MEETS OR EXCEEDS the parent's avg R after costs in both (close counts: within ~0.01R or ≥ 95%), and is not worse on avg R w/o best day or worst day by more than 0.02R / 10%; no significance hurdle (research/workbench/RULES.md). A passing variant goes straight to a testing account (no owner approval needed; ledger + assignments as usual) and takes PRIORITY there over newly rotated setups for immediate exposure. Promotion to On Deck / Primary still needs the owner.
- **Primary rules (owner 2026-11-16, PRIME-RULES with owner amendment):** Primary is guarded at both ends; no frequent rotation. ENTRY: ≥ 20 traded sessions (firm) + ≥ 5 sessions in On Deck; trades flexible by activity (≥ 40 trades for low-frequency setups, more for busy ones — judge by shrunk avg R / confidence, not raw count); avg R w/o best day > 0; best day ≤ 40% of R; owner's yes. REVIEW: Friday check weekly (report only); real decision every ~20 sessions. SLUMP of a veteran: 5-10 weak sessions = watch only (compare with its own worst historical stretch); PROBATION if the last 20 traded sessions are < 0 AND worse than its usual swing allows (e.g. below its worst prior 20-session stretch) or the −2R latch fires in ≥ 5 of 20 → flag to the owner, stays in; DEMOTE (to On Deck, never straight to Graveyard) only if probation persists 10 more sessions AND the whole-record avg R w/o best day ≤ ~0. Exception: something BROKEN (bug, data, borrow/spread change) → raise to the owner at once.
- **Primary compatibility (owner 2026-11-16):** before any setup enters Primary (and at each ~20-session review), check it cannot conflict with the setups already there: same symbol at the same time (twin/stacking, incl. leveraged/inverse ETFs by underlying), opposite sides on one name, competition for slots / buying power / per-setup caps (who loses "place in line"), and correlated same-direction exposure. Report overlap % and the R lost to blocking; a conflict NEVER withholds a promotion from a qualified setup (owner 2026-11-16) — resolve it instead: a gate / priority rule between the conflicting setups (who takes the symbol, opposite-side handling, reserved slots), or a separate Primary account for conflicting setups.
- **Effective sessions (owner 2026-11-16, corrected same day):** numbers in `config/effective_sessions.json` (one file, read by the leaderboard and by reviews via `mcf/research/effective.py`). 1 live session = 1.0 effective session (not 1.25 - owner correction). 1 calibrated replay or shadow session = 0.35 at ≥ 98% held-out match (≤ 2% extra trades, R bias within ±0.01R and never optimistic), 0.2 at 95-98% (also the weight until a setup family is calibrated, or when optimistic), 0 below 95%. 1 session of the 2-year history (full-universe backtest, no live counterpart) = 0.175, screening / experience only - never toward the On Deck or Primary minimums. Replay / shadow R gets a haircut = measured optimism + 0.02R. Replay / shadow can move a setup up the testing queue and toward On Deck; On Deck needs ≥ 5 real live sessions and Primary its full live record; if live and shadow disagree beyond noise, live wins. Shadow fills are conservative (owner): entry at the decision-time ask/bid + 0.5 × the live median entry slip (1.5 × median in all, floor 1¢), targets/limits only when traded THROUGH by max(1¢, 1 bp), stops at the stop less half the spread less 1 bp before the LR8 stop cost; fill assumptions are in each shadow journal row. Shadow mode: `mcf/execution/shadow.py` (journal run kind "shadow", id 3; never orders or account resources); nightly trust check `python -m mcf.research.shadow_calib --branches` → `research/shadow/`.
