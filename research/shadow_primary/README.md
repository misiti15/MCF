# Claude's Team (shadow)

Educational only — not financial advice. **Shadow — simulated independently; no orders.**

Owner 2026-11-05 ("full freedom"): Claude picks its best-estimate Primary book for the next session from any account and
runs it as an independent shadow next to the real Primary account. The Team changes nothing: no account config, no
promotion / demotion / move, no assignments change, no ledger "approved" entry. Every account keeps trading exactly as
configured.

## Files

| path | what |
|---|---|
| `picks/<date>.json` | the Team for a session: `{date, setups: [{id, account, side, family, why, notes}], rationale, weights}`; weights are confidence only (no sizing effect). The latest picks before a date carry over. |
| `team/<date>.json` | one Team session: trades, per-setup R / P/L, totals, actual Primary R and Alpaca P/L, cross-check, method. |
| `scoreboard.csv` | one row per run (intraday runs and the after-close run); the last row of a date is that day's result. |
| `mcf/report/team.py` | the runner: `python -m mcf.report.team --date D [--push]`. |

Data branch **`mcf-data-team`** (no PR needed, like the accounts' data branches): `team/<date>.json`, `team/latest.json`,
`picks/<date>.json`, `picks/latest.json`, `scoreboard.csv`. The dashboard card "Claude's Team (shadow)" reads
`https://raw.githubusercontent.com/misiti15/MCF/mcf-data-team/team/latest.json` (and `picks/latest.json`; before the first
push the picks on the main branch). Until a run for today exists it lists the picks with "starts <date>".

## How it runs (independent operation)

1. **Picks** - `picks/<date>.json`.
2. **Rule set** - ONE neutral set = Primary's (`config/default.yaml`): `account` (0.25% risk per trade, 77 slots, buying
   power x3.2, max positions, the **-2R per-setup daily stop**), `live` (entry / spread / participation checks; setup order
   = Primary's for its own setups, then the picks' order), `shorts`, `universe`, `costs`. Each picked setup brings only its
   own `strategies:` block from its home account (that session's frozen snapshot `setups/<date>.json` on the account's data
   branch, else the account's config file): its module, window, min ADV and exits / bracket geometry. Per-setup sizing
   keys are dropped. Account-level options of the home accounts (Testing 2's top-500 pool, Gen's refire switch, Live Lab's
   ~$1k lots, ...) do **not** apply.
3. **Universe** - the full Primary universe of the session: Primary's `universe.csv` (mcf-data, built that morning;
   min ADV $5M core + the extended tier) minus the PTP denylist and the live earnings blackout. Not any account's pool.
4. **Inputs** - read-only Alpaca market data only (never a trading endpoint): the live prep's priors
   (`mcf.data.priors.build_priors`, unchanged) and the session's 1-minute SIP bars from 09:30 to now. Cached in
   `data/team/` (git-ignored).
5. **Engine** - the as-live replay engine (`mcf.replay.harness.run_session`, the real `PaperRunner` loop; it matched
   99.5% of Primary's live trades in the audit), `fills=costs`, `limit_fill=through`, quote model from the live journaled
   spreads. Signals are generated by the Team itself; the accounts' journals are read only for the cross-check and the
   actual Primary figures.
6. **R and P/L after costs** - P/L of the simulated fills: slippage 1 bp + $0.01/share ($0.03 extended names), and
   +$0.02/share on every stop exit (the repo's stop penalty). R = P/L / (|entry - stop| x shares). Primary's actual R uses
   the live convention (pnl_adj / risk, same $0.02 stop penalty); Primary's $ is the Alpaca equity change
   (`mcf.report.reconcile_pl`), journal P/L as fallback.
7. **Intraday** - the run stops at the current minute; lots still open are marked at the last 1-minute close minus the
   exit cost (`exit_reason = "open (marked)"`). After the close the full session runs, including the 15:55 flatten.

## Refresh (hourly BDI intraday monitor + after the close)

    python -m mcf.report.team --date <today> --push

`--push` writes `team/<date>.json` + `team/latest.json` (+ picks, scoreboard) to `mcf-data-team` through a small
checkout in `data/team/branch/` (commit as mcf-bot, push with up to 3 rebase retries). Equivalent by hand:

    git fetch origin mcf-data-team && git worktree add /tmp/team origin/mcf-data-team
    cp research/shadow_primary/team/<date>.json /tmp/team/team/<date>.json && cp ... /tmp/team/team/latest.json
    git -C /tmp/team add -A && git -C /tmp/team commit -m "team <date>" && git -C /tmp/team push origin HEAD:mcf-data-team

The first intraday run of a day builds the priors (~4-8 min for ~3,400-4,900 symbols); later runs reuse them and refetch
only the bars. **Final run: after 16:05 ET** the same command scores the whole session (phase `closed`) - that row is the
day's Team result in `scoreboard.csv`. Commit `research/shadow_primary/team/<date>.json` + `scoreboard.csv` with the
nightly housekeeping (data, not setups).

Other options: `--now "YYYY-MM-DD HH:MM"` (pretend clock), `--picks FILE` (an explicit Team, e.g. a backfill),
`--label TEXT`, `--no-scoreboard`.

## Limits (read before comparing)

- **Simulated fills, not broker fills.** Stops and targets fill from 1-minute bars (stop before target inside a bar; limits
  must trade through); market entries fill at the next bar's open + costs. Alpaca paper fills differ (NBBO, partials,
  latency). The Team's $ is a model figure; Primary's $ is Alpaca's.
- Synthetic quotes (spread drawn from the live journaled spreads), no fetch latency or revised bars, shortability = the
  session's universe.csv flags; no borrow fees.
- Equity for sizing = Primary's configured $100k (the real Primary equity is ~$94.5k), so the Team's lots are ~5% larger in $.
- Intraday marks are not exits: a marked lot can still stop or reach its target later.
- The Team's picks were chosen from live records that span rule changes (~$4k Primary lot 10-28, -2R latch 10-29, CF 10-30,
  UNI1 11-04, ROLL1 11-05; research/ledger.jsonl). The Team itself runs one rule set throughout.
- A session's result is one draw. Judge the Team on many sessions, R first, with the one-big-day check.
- The **2026-11-05 run is a backfill demo** (the 11-06 Team replayed on 11-05, picked with 11-05 in view: in-sample by
  construction). It checks the plumbing; it is not a result.
